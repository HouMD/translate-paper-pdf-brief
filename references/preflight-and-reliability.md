# 首次生成的预防规则

这些规则来自首篇试译中已定位并解决的问题。目标是减少重复返工；不得把某篇论文的裁剪坐标、页边距或原文错误硬编码为所有论文的规律。开始提取前阅读，按下列阶段执行。

通用排版与检查现已实现为 [可移植模块](portable-module.md)。先使用已有CLI与配置格式，不从本案例脚本重新复制实现；下面的规则保留用于指导提取、审校和模块适用范围外的处理。

## 1. 先确定阅读顺序与运行条件

- 先确认可用 PDF 提取、渲染、排版库和宋体、楷体、Times New Roman 字体文件。优先使用工作区已有运行时；不要假定 PyMuPDF 或某个命令必定存在。缺少某个库时，可用已有的 pdfplumber/pypdf 提取、PDFium/Poppler 渲染，并验证等效结果。
- 通过当前环境提供的运行时发现机制或系统 PATH 查找工具，通过系统字体发现机制或用户配置查找字体；不硬编码解释器、字体、用户目录或插件目录的绝对位置。不假定 Windows、macOS、Linux 都预装相同字体。指定字体缺失时先说明并请用户提供字体或确认替代字体，不静默替换。可复用脚本通过参数或配置接收环境路径，以脚本位置或明确的论文根目录解析其余相对路径。
- Windows 下读写文本明确使用 UTF-8；Python 可用 `-X utf8`。避免终端默认 GBK 因版权符号等字符报错，不用删字符的方式绕过编码错误。
- 先逐页查看布局，再按每页实际栏界提取。通栏标题、摘要、跨栏图表与正文分别处理，不能将整页机械地左右平分，也不能直接信任 PDF 内部对象顺序。
- 跨栏、跨页的同一段落先拼接完整，再翻译；页眉页脚在拼接时排除。原文块保存稳定 ID、源页与区域、原文内容和图表占位符。利用段首、段尾及章节连续性核对顺序，防止摘要尾部插入正文或左右栏串行。

## 2. 裁剪时一次保全图表内容

- 图表编号、a/b 等面板标签可能是 PDF 注释对象。裁剪渲染显式保留可见注释，例如 PDFium 的 `page.render(scale=dpi/72, draw_annots=True)`；使用其他渲染器时确认等效设置。对照源页面检查标签，不能只看提取的文本或图片对象。
- 以图表、英文图注/表注、图例、标尺和所属脚注的联合边界确定裁剪框。结合文字坐标与视觉检查，确认最后一行、字母下伸部、上下标、坐标刻度都在框内；框外再留少量安全留白，但不得带入相邻正文。
- 跨页图表分块关联，保持编号。首次裁剪后立即查看全部裁剪图，再进入全文排版；发现缺行或标签缺失时在此阶段修复。
- 保存源 PDF 点坐标裁剪框、页码、dpi、物理宽高和像素宽高。若从预览图定位，使用预览文件的实际尺寸换算，明确页面旋转、裁切框及原点，不能套用固定截图尺寸。
- 截图按源裁剪框和指定 dpi 原分辨率保存，dpi 只决定像素密度。创建 PDF 时可将图表及其英文图注截图按 80%–120% 等比缩放；先调整尺寸与图文布局以减少大段空白，并检查 A4 打印适配和图中文字可读性。只有此范围内仍放不下时才使用单独页面或更大页面，禁止非等比拉伸。

## 3. 全文排版前校验字体及上下标

- 中文与西文按片段分配字体，西文从首次排版起即用 Times New Roman。不要等中文字体缺少 ñ 或数学负号时才临时处理西文。
- 字符覆盖检查必须涵盖全部将要输出的内容：标题、作者、元数据、版权符号、正文、图注、参考文献和新增注释，不只检查译文正文。重点检查 `©`、`ñ`、`−`、希腊字母、箭头及单位指数；缺字时选用能正确表达该字符的字体并记录例外，不替换为方框或删除字符。保留真正的数学负号。
- 注册并嵌入实际字体文件及所用斜体/粗体变体；生成后核对字体嵌入、文本提取和页面显示三者，不只依赖字体名称或字体覆盖表。
- 显式设置新排版行内上下标字号与基线偏移，避免库的默认参数导致下标过大、过低或撞到下一行。五号正文可从 7 pt 下标、下移 2 pt，上标 7 pt、上移 3 pt 开始；例如 ReportLab 的 `<sub size="7" rise="2">` 和 `<super size="7" rise="3">`。标题等其他字号按比例检查，不固定照搬。
- 将变量及其上下标作为不可拆分的行内单元，检查数学变量斜体、负号和单位指数。裁剪保存的原公式不重排。
- 中文全角逗号、分号等不能套用仅支持日文标点的默认换行规则。复用模块的实际字宽断行及禁则检查；英文词、经纬度数字和变量上下标不得任意截断。不把超长不可拆单元静默降级为随意断行。
- 首次全量生成前，在 tmp 内用实际标题、摘要、含上下标句子和图注做小样，检查字体、下标和“图中说明”的真实换行；小样不取代最终全文检查。

## 4. 提取修复与原文疑点分开处理

- 对断行引入的断词、连字和 DOI 空格进行修复，但先核对源 PDF。不能一律删除行末连字符，例如 `upper-tropospheric` 中的真实连字符必须保留；页码范围、负号、DOI 内部连字符也不能误删。
- 参考文献按条目而非固定行数重建，保留作者、年份、题名、期刊、卷页、DOI 和附注，检查首末条目与总数。只修复提取失真，不擅自更新原文引用。
- 翻译时对照摘要、方法、图注和结论的年份、样本量、季节月份及单位；复核百分比与分子分母、公式积分上下界与符号约定、缩写及地名一致性。
- 源页面本身存在冲突时，按原文保留并首次用【】注释，不为了全文一致而自行统一数值。语义或科学机制存疑时查阅权威术语资料及原文所引研究，区分原文陈述和译者判断；不把相关显著直接改写为已证实的因果关系。
- 只对当前文章实际存在的疑点标注。首篇论文出现过的问题不能自动作为后续论文的错误判断。

## 5. 交付前的相互补充检查

- 核对源内容块与译文块的对应、章节顺序、图表和公式数量、参考文献数量。再将最终 PDF 提取的文字与译文块比对，防止生成时漏段、重复或截断；此比对不能代替原文与译文的翻译审校。
- 比对时只规范化可解释的排版空白和上下标表示，按已知页眉页脚的位置或格式去除它们，避免页码混入跨页段落而误报。不得为通过检查而忽略实际缺字或数值差异。
- 新生成PDF采用模块的内容流顺序比对，避免几何排序把上下标移到行尾产生假缺失。页码由PDF Artifact标记排除，不能删除段首数字。仅按生成时的显式符号映射比较上下标；字面下划线和正负号必须保留。
- 图像校验同时检查像素身份、实际坐标及物理尺寸，不能只按尺寸“配对通过”。核对两个读取器的页数和图像总数，避免解析失败时零对象循环被误判通过。
- 用实际 PDF 对象坐标检查图像物理尺寸、文字与图片交叠和页面越界。行末标点悬挂应与真正越界区别，但不得遮挡其他内容或超出页面；视觉上还应检查行首孤立标点、标题孤行和图注关联。
- 逐页渲染最终版本，检查全部页面及放大的裁剪图。修复后重新检查受影响页面和分页变化区域。将实际检查结果保存到该论文的 tmp 内，不以脚本执行成功代替质量验收，也不预先承诺所有新 PDF 都能一次通过。
- 优先复用由内容哈希确认未变化的裁剪与预览。首次目检全部页面；修订仅对未获有效目检的变化页面重新查看。保留PDF哈希对应的自动报告和页面哈希对应的目检记录，不重复渲染已验证且未变化的页面，也不借缓存跳过改变后的检查。
